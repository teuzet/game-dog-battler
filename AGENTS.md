# Как устроен этот репозиторий

- `Game.Core/` — детерминированное игровое ядро на чистом C# (netstandard2.1, без Unity). `GameSetup.cs` — точка сборки: какая это игра и её модули в порядке тика. `Modules/<Модуль>/` — модули, `Bots/` — боты, `Sim/` — симуляция, события, ввод, форки, `Math/` — `Fixed`, `DetRandom`, `StateHasher`, `Data/` — числа игры (`*.json`), архетипы ботов (`bots/`) и варианты (`variants/<набор>/<имя>.json`).
- `Game.Core.Tests/` — xUnit-тесты. `Contract/` — инварианты фабрики (детерминизм, форк, пустой ввод, конец сессии, лог ввода, теги темпа, граф модулей против `MODULES.md`); их не правят, чтобы позеленеть. Каждая фича добавляет свои тесты рядом.
- `Game.Sim/` — консольный раннер сессий ботов для тула `sim`: `metrics.json`, хроники, `sessions.jsonl` с тегами темпа. `--replay <inputs.txt>` повторяет сессию Nick.
- `Unity/` — Unity-проект: только рендер состояния и сбор ввода. Оболочка (вход, ввод, рестарт, опрос, варианты, сборка демо) — из `UnityShell/`, см. его README. Ассеты — в `Unity/Assets/Art/`.
- `MODULES.md` — карта модулей: чем владеет каждый и от кого зависит. Правит техлид.
- `design/` — `overview.md` (ядро геймплея, «Почему это весело», карта темпа, архетипы ботов), `stories.md` (юзерстори игроков, отмеченные Nick), диздоки фич `F-xxx.md`.
- `sprints/S-N.md` — цель спринта от лица игрока, ревью продюсера, ретро техлида.
- `playtest/` — `sim.json` (как запустить раннер), `pace-targets.json` (коридоры карты темпа и пороги гейта), отчёты `sprint-N.md`, прогоны `sprint-N/run-*`, `ledger.md` (журнал: вердикт Nick рядом с метриками ботов), `nick/S-N/` (опросы и логи ввода из демо).
- `art/` — `style.md` и превизы; `brainstorm/` — сырые ответы тула brainstorm.
- `features.json` — фичи; правит только техлид. `decisions.md` — решения уровня проекта. `discuss-later.md` — вопросы без ответа Nick. `progress.md` — что влито.
- `.factory/` — служебные файлы диспетчера. Не коммитить.

## Правила для всех
- Детерминизм: в `Game.Core` без `DateTime.Now`, `System.Random`, `float`/`double` в состоянии, порядка `Dictionary`/`HashSet` в логике. Дроби — `Fixed`, случайность — свой поток модуля `sim.Rng(this)`.
- Модуль владеет своей подсистемой целиком. Другой модуль читается только через `sim.Need<T>(this, имя)` и только если он есть в `DependsOn` и в `MODULES.md`. Новая связь — правка карты техлидом, не попутно.
- События, которые важны игроку, пишутся в `sim.Events` с тегами темпа: `DecisionOptions`, `Threat` (0..1), `Reward`, `Novel`. Без них карта темпа пуста и гейт фана не пройти.
- Боты видят только `BotView` из `IGame.Sense` (то, что на экране), реагируют с задержкой и держат решение (`reaction_ms`, `hold_ms`). Стратегия — пара предложений в `about`. Обязательны `idle`, `random`, `smart`.
- Числа игры — в `Game.Core/Data/*.json`, не в коде. То, что сравнивают, — вариантами в `Data/variants/`.
- Без защитного кода «на всякий случай»: невозможное состояние — исключение, а не тихий возврат.
- `touches` фичи — прогноз для расписания, а не запрет. Правь то, что нужно чистому решению, но минимально. Прежде чем писать помощник, поищи (`grep`) готовый.
- Один исполнитель — одна фича — одна ветка `feat/F-XXX`.
- Работа идёт спринтами: спринт кончается взломщиком и плейтестом, потом гейт фана, демо Nick, ревью и ретро; следующий не начнётся, пока предыдущий не закрыт.

## Правила этой игры (Dog Battler)
- Единицы ядра: метры, секунды, массы в у.е. из `design/roster.md`; в данных секунды и метры, тики считает код. Ввод мыши — сантиметры арены в `PlayerInput.AimX/AimY`.
- Симуляция в плоскости XY; Unity кладёт её на землю XZ. Высота, рэгдоллы, 3D — только вид, в ядро ничего не возвращают.
- Классы — внутри своего модуля: породы `Modules/Dogs/Breeds/`, типажи `Modules/Owners/Types/`, объекты `Modules/Props/Kinds/`, правила `Modules/Rules/<Имя>/`. Новый класс = файл + json + строка реестра; карту модулей не меняет.
- `Bodies` не знает игровых слов (собака, хозяин, удар): смысл живёт в `Dogs`, `Owners`, `Hits`. Правила не знают пород: «в зоне ли игрок» спрашивают у `Dogs`.
- Хозяин неуязвим: у хозяина нет здоровья ни в одном модуле.
- Оба режима мыши (толчок и курсор) живут в `Control`; фича, меняющая управление, проверяет оба.
- Имена событий: `hit`, `strong_hit`, `near_miss`, `knocked_out`, `zone_announced`, `lead_change`, `final_seconds`, `wrap`, `tangle`, `untangle`, `arena_event`, `ability`; теги — по `design/overview.md` → «Теги событий».
- Цвет игрока по индексу (красный, синий, жёлтый, фиолетовый…), на ошейнике, поводке и акценте хозяина (`art/style.md`).
